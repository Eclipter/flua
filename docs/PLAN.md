# Remaining implementation plan

This plan tracks the remaining native wallpaper work and outstanding validation. Current support is listed in `FEATURES.md`. Community features, profiles, network services and third-party runtime dependencies are outside its scope.

The native-provider playback and file-access feasibility gate has passed on the tested OS. Step 2 is implemented in the library model. The app build connects the library catalog and explicit setup to System Settings. Explicit native Apply resolves the app’s saved surface model, saved native launch restoration is implemented, and automatic routing of Lock Screen, mode, link and display-mode changes to active native displays is in place. Physical multi-display validation, sleep/wake, animated scene idle, long-duration locking, revoked sandbox tokens and broader recovery scenarios in step 6 remain outstanding.

A sandboxed probe could not read the external fixture before the host supplied a file wrapper; image/video sessions then held an active scope. Real lock/unlock updates were observed, and the user confirmed visible motion on the Lock Screen. Playback continued with the disposable containing application exited. Removal and restoration to a readable baseline were verified. A further real-host check verified video Animated/Still and aurora Still screen-saver transitions, plus brief aurora Still lock/unlock, with the containing harness exited. See the [transition scope](../Sources/WallpaperExtension/README.md#native-locked-and-idle-transitions) and the [observations and restore procedure](../Sources/WallpaperExtension/README.md#real-host-feasibility-result).

Verify actual desktop, locked and idle presentation, including continued playback after the test application exits. **Done within the tested scope:** host rendering, visible video Lock Screen motion, brief aurora Still lock/unlock and video Animated/Still and aurora Still real screen-saver transitions are verified with the containing harness exited. ## 2. Model desktop and Lock Screen assignments separately

**Status:** done in the library model. Deterministic tests and the isolated smoke run pass. The desktop overlay engine applies and restores only the desktop surface. A stored desktop Still mode is rendered as a retained frame. Explicit native Apply consumes saved surface selections, links and modes for the targeted displays; saved native launch restoration is implemented.

1. Extend `DisplayAssignment` with per-surface selection and persistent Animated/Still mode, plus a linked/independent setting. Keep this separate from the existing Mirrored/Per Display setting. **Done.**
2. Decode old assignments into the desktop surface with their playlist index, history and timing intact. Leave the Lock Screen unmanaged until the user assigns it or enables linking. **Done.**
3. Define linking to copy the desktop selection and mode to the Lock Screen and follow subsequent desktop changes. Unlinking preserves the current values for independent editing. **Done.** A change made for either linked surface updates both.
4. Update assignment changes, mirrored synchronization, playlist advancement, removal, stopping and restoration to respect the selected surface and link state. **Done.** Mirrored mode copies the whole desktop/Lock Screen pair, including modes and link state. Desktop apply, playlist advancement and stop leave an unlinked Lock Screen choice in place.
5. Keep assignments keyed by stable display UUIDs, retaining disconnected displays' saved choices for reconnection. **Done.**

**Acceptance:** deterministic tests cover legacy decoding, link/unlink, independent modes, mirrored displays, playlist advancement, removed content and persistence. **Met** by `make test` and the assignment checks in `make smoke`. Physical multi-display behavior remains unverified.

## 3. Implement Animated and Still rendering for each surface

1. Extend `Engine.swift` so Still is a persistent rendering choice rather than the temporary global pause state. **Done** for the desktop surface.
2. Generate and retain still assets for videos and procedural scenes. Use the chosen video thumbnail frame, respecting valid trim bounds; images remain still in either mode. **Done.** Files are written under `Stills/` and the source file is left unchanged.
3. Extend the provider configuration and renderer to honor per-surface modes and supported trim, speed, fit and dimming settings. **Done.** Catalog rows carry speed, dimming, fit, a valid video trim, the still-frame time, and one desktop mode and one Lock Screen mode. Conflicting per-display modes publish Animated. The renderer applies that configuration; idle presentation uses the Lock Screen mode. Suspension and resume leave the saved mode unchanged, and the source file is not modified. Standalone tests also verify video and scene Still frames across idle suspension/resume and return to animated desktop playback.
4. Provide native animated output or locally prepared loop assets for the four built-in scenes before exposing them as animated native choices. **Done.** The provider draws aurora, cosmos, ocean and ember into the session surface, so no loop file is required. `catalog.json` lists an unblocked scene with an empty file path, its speed and dimming, and still time 7 (the desktop thumbnail). A video badge exposes that row as an animated choice. Suspension and resume leave the saved mode unchanged. The app applies these rows directly from Flua and also publishes them to System Settings; real-system results are recorded in the provider documentation.
5. Keep temporary suspension, resume and lock/idle transitions separate from the saved mode. Avoid desktop-overlay and system-provider playback competing for the same desktop. **Partial:** pause and resume leave the saved desktop mode unchanged. Successful native desktop apply removes the targeted overlays to avoid competing playback. Real video Animated/Still and aurora Still idle transitions pass on one built-in display; sleep remains unverified.

**Acceptance:** deterministic configuration checks and runtime tests show that surface modes survive restart, suspension and resume without altering source media.

## 4. Connect the library to the provider and System Settings

1. Publish a small versioned local catalog containing stable IDs, configuration, thumbnails and references to durable library-owned assets. Write it atomically instead of exposing partially saved application state. **Done.** `catalog.json` is written beside `library.json`. It lists image and video files under `Media/`, and the four built-in scenes with no media file. It omits other kinds, blocked tags and unsafe filenames. Video rows and scene rows still use the prototype thumbnail.
2. Give the provider the read access proven in step 1. **Done for the app build.** The sandbox reads only `catalog.json` through a file-specific exception. Media stays on host wrappers. `FLUA_CATALOG_PATH` binds disposable integration builds to an isolated library; setup rejects a mismatched library. Existing catalog version, ID and containment validation remains in place.
3. Populate the desktop and screen-saver catalogs from eligible library entries. **Done for native library discovery and refresh on the tested OS.** The native build hides prototype fixtures, lists library image/video and scene rows, and respects blocked tags. A real library-video choice acquired scoped files and looped in WallpaperAgent. Atomic catalog replacement updated the selected title in System Settings. A cached-choice acquire also starts catalog refresh when the host does not request settings again. Playback-setting edits automatically refresh matching active descriptors after a short delay. Deterministic checks and real-host edit refresh pass on macOS 27.0.1 with one built-in display; see the [verification scope](../Sources/WallpaperExtension/README.md#native-launch-restoration-and-edit-refresh).
4. Resolve per-display desktop/Lock Screen choices and host idle requests without adding a third independent assignment surface unless required by the host. **Implemented:** explicit native Apply resolves saved independent or linked surface choices and modes for targeted displays across existing Spaces, preserving unassigned system surfaces and untargeted overrides. Deterministic tests cover resolution, inheritance, metadata retention, verification and rejection. Physical multi-display validation remains outstanding.
5. Keep selected assets and configurations available after Flua exits. Handle missing media, stale choices and incompatible catalog data with a usable still fallback or a recoverable error. **Implemented:** missing, inaccessible or undecodable image/video media renders the static provider gradient without modifying the saved descriptor. Failed active AVFoundation rebuilds also switch to the static gradient and retry the original host wrappers every five seconds while unsuspended; absent or unusable wrappers require explicit Apply after restoring media/access. Cached descriptors with valid host wrappers continue to render when the catalog is absent or incompatible; unsupported descriptor versions return an error. Standalone recovery checks cover these paths. Real-host image recovery and explicit Apply after permission failure or provider termination are verified within the scope recorded in step 5.4; recovery from initially undecodable video and explicit reapply after termination are verified in the [video recovery check](../Sources/WallpaperExtension/README.md#native-video-recovery). Active video path removal and in-place truncation/recovery have also been checked; revoked tokens and longer/other active-loss scenarios remain unverified.

**Acceptance:** a real library import appears in System Settings, renders through the sandboxed provider and keeps playing after Flua quits. **Met for the tested native library video on macOS 27.0.1.** The user confirmed motion during a real lock/unlock with Flua closed. The provider logged continued frames and loops, and an atomic catalog replacement updated the selected title in System Settings. Per-display native resolution is implemented; physical multi-display validation and the remaining recovery scenarios in step 5.4 remain outstanding.

2. Add Desktop/Lock Screen targeting, link/unlink and Animated/Still controls in the inspector. Show each surface's effective assignment and mode. **Done:** controls edit saved assignments for the targeted displays and show mixed assignments when needed. Isolated smoke checks cover independent choices, link/unlink, linked modes and persistence; the controls were visually inspected in a disposable library.
3. Route apply, stop, edits and restoration through the appropriate desktop engine or native-provider path. **Partial:** native Apply uses saved independent or linked assignments and modes for targeted displays, independent of the Settings catalog cache. A successful native desktop apply removes targeted overlays without clearing assignments. Desktop playback remains available when native setup is unavailable. Automatic refresh after speed, dimming, fit, trim and still-frame edits is implemented with a 0.5-second debounce, preserving active surface modes and unrelated choices. Saving a Lock Screen choice, changing a surface mode or link state, and switching Mirrored/Per Display now queue the latest saved state for connected displays with active native intent, using the same debounce. Before replacing a native assignment, the store restores Flua-owned surfaces from the retained baseline, so cleared surfaces do not keep stale Flua choices. Descriptor checks pass; native Stop restores both targeted surfaces from a separately retained pre-apply baseline, preserving saved choices and foreign wallpapers. If Flua is already selected and no baseline exists, Apply updates that choice in place. Stop without a baseline fails without changing the system store. Repeated applies retain the restoration baseline. Deterministic restoration checks and a real-host repeated-Apply/Stop check pass on macOS 27.0.1 with one display; both wallpaper stores and disposable registration were restored. Successful native Apply now persists per-display playback intent; launch reapplies active assignments and keeps stopped displays stopped. Unsupported or mismatched builds restore desktop playback while retaining native intent. Legacy libraries keep desktop restoration. Model tests and isolated smoke checks cover persistence, stopped launch and unavailable-native fallback. Real-host edit refresh, separate-process native launch restoration and stopped relaunch pass on macOS 27.0.1 with one built-in display. The check retained independent video/Still Desktop and scene/Animated Lock Screen descriptors, rapid playback edits and the original baseline, with no competing overlay. Both stores and provider paths were restored. A real-host check on arm64 macOS 27.0.1 (26A434) with one built-in display changed the saved Lock Screen scene from Northern lights (`aurora`) to Deep space (`cosmos`); all 13 test-provider `Idle` descriptors updated without a second Apply while native intent remained active.
