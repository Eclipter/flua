# Architecture

Flua is a local SwiftUI/AppKit application for Apple Silicon Macs running macOS 27 or later. The main app has no third-party runtime dependencies. macOS owns wallpaper playback through the embedded provider; the app has no desktop overlay playback engine.

## Application and library

- `App.swift` owns application lifecycle, windows, the internal Settings page, menu bar and library views. Settings uses the library section selection and hides the wallpaper inspector and transport controls. Shared controls honor the selected accent and Reduce Transparency. Menu bar and Dock visibility are persisted; hiding the Dock requires the menu bar icon to remain enabled.
- `Focus.swift` owns the shared focus-clearing AppKit view and segmented-picker tab target selection, compiled directly by the focus tests. `App.swift` supplies the verification-window setup callback.
- `Library.swift` owns observable library state on `MainActor` and coordinates browsing, imports, edits, persistence, playlists and native playback. A two-second timer advances both independent surface playlists when due, processing linked surfaces once. Playlist Start/Previous/Next use the selected surface. Advancement applies only changed displays and preserves the other independent surface; stopped displays stay stopped during automatic advancement. Pause/Resume playlists controls automatic playlist advancement without changing wallpaper animation. Online downloads enter through the same media validation and copy boundary as local imports; source attribution commits with the wallpaper record.
- `Model.swift` contains backward-compatible Codable state, filtering, media classifications and playlist transitions. Display assignments use stable UUIDs and retain disconnected displays. Each stores Desktop and optional Lock Screen choices with separate modes and playlist state. Linking synchronizes both surfaces. Entering Mirrored mode synchronizes the whole pair across connected displays; playlist transitions synchronize only the advancing surface across eligible displays.
- `LibraryPaths.swift` resolves the library root and validates isolated verification launch arguments before library access. `ImageThumbnail.swift` creates orientation-correct image thumbnails with a 480-pixel maximum edge; `MediaFacts.swift` uses the same ImageIO helper to classify color from 64-pixel local media thumbnails.

`LibraryDisk` in `Model.swift` atomically replaces `library.json` as the library commit, then queues a snapshot of the derived `catalog.json` separately. Catalog encoding and atomic writes run on one background queue in submission order. Unchanged provider data, including favorite-only edits, reuses the last successful publication while the file identity and attributes still match; deletion, replacement or a failed publication forces a retry. Manifest failure rejects an edit and restores its previous in-memory state. Catalog failure keeps the committed edit in memory and on disk, reports a separate publication error, and retries publication on the next save; native playback may retain the previous catalog until publication succeeds. Native Apply and edit refresh await the current catalog before constructing descriptors. Quitting drains queued writes and flushes a pending thumbnail batch. Imported media is copied under `Media/`. Direct media imports resolve symbolic links and copy the regular target file, keeping the library independent of the source. Removing an entry retains its copied media. An unreadable library manifest leaves the original file untouched and blocks saves and imports for that session.

`OnlineCatalogBrowser.swift` coordinates live collection queries, per-source pagination, cancellation, retries and incremental results. `OnlineCatalogProviders.swift`, `OnlineCatalogPublicProviders.swift` and `OnlineCatalogStockProviders.swift` implement the six publisher contracts. The National Park Service indexes are finite archives loaded in full and searched locally; the other providers use their published search or pagination endpoints. Collection requests start when Discover opens or a search is submitted. Preview media is requested only after the user chooses Preview. `OnlineRangePreview.swift` builds a temporary silent excerpt from HTTPS byte ranges: it checks the server’s exact range response, inspects AVFoundation sample references with external-reference loading forbidden, downloads any uncovered sample bytes under the per-item cap, and exports only the requested video segment. The temporary excerpt is deleted when the preview closes. Dareful’s published HLS stream requests a preferred 640×360 resolution and 800 kbit/s peak with a two-second playback segment.

`OnlineWallpaperDownload` accepts validated provider routes and media files under 1 GiB. Static downloads allow only same-host HTTPS redirects. For Cute Stock Footage, it fetches the public item page with an ephemeral, cookie-free URLSession, enforces a 2 MB HTML bound, extracts the current signed Vimeo link for that exact clip, then permits only the observed HTTPS Vimeo player and progressive CDN hosts. Preview and download each resolve a fresh signed link; signatures are never stored in library metadata. The completed response is written to a temporary file. `Library.importMedia` validates the file as a self-contained image/video, copies it into `Media/`, and saves source, creator, license and modification notice with the wallpaper. Catalog IDs prevent duplicate records; missing downloaded files can be repaired without replacing user edits. A failed manifest save rolls back the added or repaired entry and its staged media. Opening the local library does not query the online catalog.

The versioned provider catalog publishes eligible images, videos and the eight built-in scenes. Older libraries add the four new scene entries once when decoded, without restoring removed original scenes; a saved catalog version preserves later removals. Rows contain stable IDs, media references, speed, dimming, fit, video trim, still time and surface modes. As library thumbnails become available, `Library` batches their publication as JPEG data URLs in the catalog without rewriting the library manifest. `LibraryDisk` retains those previews across subsequent saves; thumbnails are regenerated on launch. The provider uses each preview for both the Settings item and its choice, accepting only bounded inline JPEG URLs without granting access to additional files or network resources. Missing or invalid previews retain the bundled fallback. The catalog and each choice descriptor carry playback preferences; missing policy and thumbnail fields in older catalogs remain compatible. Scene still time is 7; conflicting display modes publish Animated for that surface. Blocked or unsafe entries are omitted.

UI state in `Library`, `ViewState` and `AppContext` belongs to `MainActor`. AppKit notification handlers scheduled on the main queue and main-run-loop timers enter that actor explicitly; view cleanup uses isolated deinitializers. Catalog workers receive immutable `ProviderCatalog` values. Native Apply freezes its property-list dictionaries into an in-memory binary snapshot before detached work decodes its own copies. Package inspection, file copies, media inspection and native wallpaper transactions stay off the UI actor; their results update library state on that actor.

## Previews, editing and imports

`Engine.swift` provides `MediaSurface` for app previews and display identification. Video and scene previews pause when hidden, offscreen or fully occluded. Video previews are explicitly silent. The inspector passes the configured surface’s draft rendering mode to its preview, using Animated when target displays have mixed modes. Still previews use the selected video cover time within its trim range, or the built-in scene at time 7; returning to Animated restarts playback.

`SceneView.swift` hosts a `CAMetalLayer`. `ScenePreviewRenderer.swift` owns its display link and preview controls on `MainActor`, while a serial worker receives frame settings as immutable values and submits Metal commands. Metal resources are shared after construction; the seed buffer remains read-only. `ScenePreview.metal` renders eight scenes at up to 60 fps at the window's Retina backing scale. Artwork scenes are capped at 2048 pixels on the long edge and 2,073,600 pixels total; the earlier procedural scenes remain capped at 1280 pixels and 144,000 pixels total. Both limits preserve the view aspect ratio, with one frame in flight. A busy GPU skips frames; failed setup shows a still preview. The four newer scenes animate their generated `SceneAssets` artwork: mist, birds and six separate pine sprites over Ink Mountains, windblown grains and dust plumes over Sahara, streamlets along Contour Atlas waterways, and ink pigment blooms and trails over Optical Current. Ink Mountains artwork, including its painted pines, stays fixed; the added pine sprites sway gently around their anchored roots. `SceneDrawing.swift` crops three transparent pine images from `ink-pines.png` and uses them in six deterministic sprite placements. The pines use the existing instanced textured-sprite pipeline in both Core Graphics and Metal; no artwork pixels or sampling coordinates are warped. Ink Mountains and Sahara use a 2× base motion rate; Contour Atlas and Optical Current use 1×. Sprite positions, images and per-art alpha masks are shared between the Core Graphics reference and Metal preview. The GPU draws sprites with premultiplied-alpha blending; a final pass dims the completed composition once. Core Graphics supplies the reference used for thumbnails, still frames and provider rendering at up to 24 fps. Smoke verification checks frame progress and compares GPU composition pixel checksums over time for the four artwork scenes.

`Editor.swift` owns draft video trim/cover edits and portable package export. `ImageExport.swift` stages image copies beside the destination and replaces existing files only after save-panel confirmation, while rejecting source aliases. Video package export refuses an existing destination. Export composes video tracks only, omitting source audio. Save Changes merges only video edits into the current library record, preserving details and playback settings changed while the editor was open; Cancel or closing discards drafts. `ScenePackage.swift` validates package manifests, paths and ZIP contents before copying media. Source files are preserved. Global imports reveal the added batch and retain IDs for Undo; playlist imports receive an explicit destination.

## Native wallpaper boundary

`NativeWallpaper.swift` registers and verifies the current containing app and extension, checks the catalog path, serializes transactions and invokes `FluaWallpaperGuard`. The helper validates the current-user WallpaperAgent executable and pauses it while the store is read and replaced. Commit restarts the agent; EOF, timeout or handled termination resumes an abandoned transaction.

`NativeWallpaperStore.swift` validates the private store format and resolves saved choices into Desktop and Lock Screen descriptors across targeted displays and existing Spaces. Per Display also reads live Space UUIDs from WindowServer and seeds missing store entries with their inherited choices before applying overrides; a sparse global store must not leave the ordinary Desktop on its previous wallpaper. When both choices are Flua assignments, it composes them into a v2 pair for the provider: each nested v1 config describes one surface and indexes into the union of their host-supplied file wrappers. It preserves unrelated metadata and choices; it does not read or package another provider's media. Per Display retains the global choice as the default fallback and writes targeted overrides; Mirrored updates defaults and targeted assignments. Missing or blocked saved items abort application.

During Per Display Apply, macOS can copy requested surface choices into `SystemDefault` and existing Space defaults. Apply verification and its unchanged-assignment check accept those exact choices on the matching surface while still requiring all targeted assignments and every other store value to match apart from host timestamps. Stop, removal and Mirrored verification retain their strict comparisons.

`NativeWallpaperBackup.plist` and `NativeWallpaperBackup-v2.plist` back up the last transaction for each wallpaper store. `NativeWallpaperBaseline.plist` retains previous system choices across repeated applies and edits. Normal Apply overlays only the selected assigned surfaces and preserves unassigned surfaces and untargeted displays, including their inherited choices. Stop restores targeted Flua surfaces while retaining library selections. Missing, unreadable or unusable baseline surfaces fall back to the native macOS `default` choice during Stop and provider removal; valid saved surfaces and later foreign choices are preserved. Provider removal restores remaining Flua surfaces in both wallpaper stores, unregisters the exact app/extension paths and repeats restoration to clear cached host choices. Library media is preserved.

`LibraryState.nativePlayback` records active or stopped intent per display. `nativeCleanupDisplays` durably marks displays whose removed assignments still need native cleanup, so a later reconnect or assignment refresh can finish cleanup if Flua exits before its deferred refresh. Opening Flua leaves the current system wallpaper unchanged; it does not reapply saved choices. Saved playlists wait until playback is applied again before automatically advancing, including explicit Apply, playlist start, manual advancement, reconnection or assignment refresh. Reconnection compares saved assignments with the system store and provider registration; matching choices continue without a reload. Changed assignments use guarded Apply. Stopped displays skip restoration and automatic advancement. Unavailable or mismatched builds retain intent without applying wallpapers. Explicit Apply reloads even unchanged choices to permit recovery after termination.

The inspector keeps display mode, surface linking, rendering modes and fit/speed/dimming edits in memory as a preview draft. Set Wallpapers commits that draft and assigns the selected wallpaper to the chosen surface on the target displays: the selected display in Per Display mode, or every connected display in Mirrored mode. Linked Desktop and Lock Screen choices remain synchronized, and each target surface keeps its rendering mode. Configuration drafts store only pending display mode, surface linking and rendering mode changes and merge them into the current assignments for preview and application. Removing a wallpaper or advancing a playlist while a draft is open therefore does not restore stale assignments. Drafts do not enter the persisted library or provider catalog before application. Editor playback edits and removal of active assignments are coalesced for 0.5 seconds. Parameter refresh matches provider, kind and media URLs, preserves surface modes and unknown configuration fields, and skips no-op reloads. Removal refreshes first restore Flua-owned surfaces from the baseline, preventing deleted choices from leaving stale selections. Ordinary Apply, reconnection restoration and playlist changes overlay saved choices without clearing unassigned surfaces.

## Provider

`Sources/WallpaperExtension/` is a separate compile boundary using private macOS protocols. `make build` embeds a sandboxed provider under `Contents/Extensions/`. Its file-read exception covers only `catalog.json`; media access uses host-supplied scoped wrappers. `FLUA_CATALOG_PATH` and `FLUA_WALLPAPER_IDENTIFIER` select disposable integration builds. A normal launch without `--data-dir` opens the directory containing that catalog, or the default support library when no catalog is bound. Smoke, startup, preview, scroll, and accessibility verification require an explicit `--data-dir` that does not overlap the Flua support library and disable native wallpaper operations. `FLUALibraryOnly` hides standalone prototype fixtures.

The provider watches catalog writes and atomic replacements, including acquisition from cached host choices. It accepts legacy v1 single-content descriptors and v2 paired Flua configs. `default` uses the paired Desktop config; locked and idle use the Lock Screen config. When those configs differ, the provider rebuilds media and replaces the layer on the existing remote context, retaining the wrapper union for recovery. Suspension preserves the selected content and its saved mode. A real-host check confirmed the v2 switch for cosmos Desktop and ember Still Lock Screen on one built-in display. File-media pairs, mixed Flua/non-Flua pairs and multiple displays remain unverified. `PlaybackPolicy.m` reads IOKit power sources and macOS Low Power Mode once per second while moving non-preview sessions have enabled power rules. The provider queries managed Spaces at 30 Hz only when a moving Desktop session with display affinity enables fullscreen pause, excluding previews and host-suspended sessions. It adjusts the timer on catalog and host updates; static content, previews, host-suspended sessions and sessions without any applicable enabled pause rule have no policy timer. The provider combines preference pauses with host suspension and resumes only when both clear. Preferences continue working without the main app: catalog replacements update active sessions, and the last valid catalog policy survives transient read failures. On a cold start without a readable catalog, cached descriptors provide the fallback policy. Previews ignore preference pauses. Fullscreen applies only to Desktop presentation on the request’s `directDisplayID`; missing display affinity or unavailable private Space APIs leave fullscreen pause inactive. Power pauses also apply to locked and idle playback. Missing or undecodable media uses a static gradient; a five-second retry while unsuspended can rebuild the selected renderer in the same remote context. Missing or unusable wrappers require explicit reapply for fresh grants. Cached descriptors can render independently of the catalog; unsupported descriptor versions return an error.

Protocol details and recorded host checks live in the [provider documentation](../Sources/WallpaperExtension/README.md) and [protocol reference](../Sources/WallpaperExtension/PROTOCOL.md).

## Verification boundary

`make test` covers the download transport's success, HTTP failure, redirect rejection and cancellation through a deterministic URL protocol; media-import tests cover duplicate downloads, missing-file repair and invalid or external-reference media. `make smoke` checks bundled catalog metadata and source attribution through package export/import in isolated workflows; it disables system Apply, Stop, restoration, refresh and removal. Native host behavior is tested separately. See [DEVELOPMENT.md](DEVELOPMENT.md) for procedures, [FEATURES.md](FEATURES.md) for support and [PLAN.md](PLAN.md) for unresolved work.
