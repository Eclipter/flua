# Architecture

Flua is a local SwiftUI/AppKit macOS application. `App.swift` creates the shared library and owns windows, settings and the menu bar. Menu bar visibility and Dock hiding are stored on `LibraryState`; the Dock icon is hidden with accessory activation only while the menu bar icon is enabled, and that choice is cleared when the icon is turned off. Legacy libraries omit both keys and keep the icon and the Dock icon visible. `AccentColor.swift` defines the macOS accent palette and its menu swatches, with light/dark variants checked against AppKit by standalone tests. `App.swift` also shares the frosted material surface, button, text-field and menu-picker styles, segmented choice control, classification color labels and accent backdrop with the video editor; these use macOS 15 SwiftUI materials and honor Reduce Transparency for custom surfaces. `Library.swift` coordinates UI actions, persistence and playback. `Model.swift` contains backward-compatible Codable state, exact-tag normalization, browsing/filter rules, media buckets and playlist transitions. Each display assignment stores a desktop choice and an optional Lock Screen choice, each with its own playlist position and Animated/Still mode. Older assignments load as desktop-only. Linking keeps both choices identical; Mirrored mode copies that whole pair between connected displays. `Library.swift` plays and restores the desktop choice through the overlay engine; when native intent is active, it also routes saved Lock Screen, mode and link changes to the native provider for connected displays. Desktop Still reads a retained PNG under `Stills/` (the video thumbnail frame inside a valid trim, or a procedural scene frame) and does not modify files in `Media/`. Images stay still in either mode. `LibraryPaths.swift` resolves the application's local library directory.

`MediaFacts.swift` measures local image/video facts and classifies a bounded thumbnail off the main thread. `Library.swift` records successful import dates, backfills legacy facts and routes Discover and collection views through the same model rules. Blocked tags affect browsing while preserving playback assignments.

`LibraryDisk` in `Model.swift` atomically writes `library.json` and `catalog.json`, and resolves imported files under `Media/`. `catalog.json` lists eligible image and video files for the wallpaper provider, plus the four built-in scenes with an empty file path. Each row includes speed, dimming, fit, a valid video trim when the media has one, the still-frame time, and one desktop mode and one Lock Screen mode. Scene still time is 7, the same frame the desktop thumbnail uses. Conflicting per-display modes are published as Animated. The provider reads `FLUA_CATALOG`, a bundled `catalog.json`, `FLUACatalogPath`, or the live catalog when it is running as an appex. If the file is unreadable it asks the host for read-only access and pushes a settings update; an atomic replacement or write of that file pushes again. It applies the row's playback settings. Scene rows are drawn in the provider at up to 24 fps. The drawing uses the desktop cap of 1280 pixels on the long edge, then each finished frame is scaled to the full destination and published; speed and dimming apply. Idle presentation uses the Lock Screen mode. It does not read library media bytes from the sandbox; those stay on the host's file wrappers. An unreadable manifest leaves the saved library untouched: `Library.swift` uses the initial scenes in memory and blocks saves and imports for that session. Removing a library entry retains its copied media file.

`Engine.swift` maintains click-through desktop windows and AVFoundation playback per display. Still mode keeps a static image in that window; the global pause flag, and the engine's sleep and lock suspension, do not change the saved mode or start a still surface. `SceneDrawing.swift` draws the four procedural scenes. `SceneView.swift` plays them on the desktop at up to 24 fps, drawing into a surface capped at 1280 pixels on the long edge. The wallpaper provider compiles the same drawing with optimization and publishes finished frames at that rate. `Editor.swift` previews and exports media without overwriting source files. `ScenePackage.swift` validates manifest folders and ZIP containers before imports copy media into the library. `SmokeRunner.swift` runs only when explicitly requested with isolated test paths.

`NativeWallpaper.swift` applies saved native assignments directly: it registers the running containing app and extension, removes other copies of that extension identifier, verifies this copy is the one macOS will run, locks the wallpaper store against concurrent Flua applies, and starts `FluaWallpaperGuard`. The helper validates the exact current-user WallpaperAgent executable and pauses it while the app reads and atomically replaces `Store/Index.plist`. `NativeWallpaperStore.swift` validates the private store format, preserves unrelated metadata and resolves each targeted display’s saved Desktop/Lock Screen choices and modes into separate descriptors, including linked assignments and still images. Missing or blocked saved items abort application. Unassigned surfaces retain their effective system choice, including conversion from a linked system wallpaper. Mirrored application updates defaults and targeted display/Space assignments; Per Display retains the previous global choice as the default fallback and writes only targeted overrides, with `$null` for the global override. The previous store is backed up as `NativeWallpaperBackup.plist` in the library. The helper restarts the agent after a successful write; EOF, timeout or handled termination resumes it if the transaction is abandoned. The app verifies the persisted descriptors before reporting success. Explicit Apply updates the surface timestamps and reloads the host even for the same saved choices, allowing retry after provider termination; no-op playback-setting refreshes still skip reload. `Library.swift` first saves the catalog and rejects a build configured for a different library. Flua writes the resolved descriptors and media URLs directly, avoiding dependence on the system Settings catalog cache. macOS owns playback after explicit application. Successful native desktop application stops the targeted overlays without clearing saved assignments. When saving a Lock Screen choice, changing a surface mode or link state, or switching Mirrored/Per Display mode while a display has active native intent, `Library.swift` coalesces the latest assignments for connected displays with active native intent and applies them after 0.5 seconds. Before replacing assignments, `NativeWallpaperStore.swift` restores Flua-owned surfaces from the retained `NativeWallpaperBaseline.plist`, then writes the current saved choices; a cleared surface therefore returns to its baseline instead of retaining a stale Flua choice. Native Stop uses the same guarded transaction to restore both targeted surfaces from the baseline, retaining saved library assignments. Before each native Apply, baseline capture retains prior foreign surface settings while refreshing surfaces changed outside Flua. If Flua is already selected and no baseline exists, Apply updates those choices in place. Mixed-provider surface choices and Stop without a baseline fail without writing the system store. Mirrored Stop restores defaults as well as targeted overrides; Per Display materializes restored overrides while preserving inherited choices for untargeted displays. Verification ignores only host-maintained LastSet/LastUse timestamps. `LibraryState.nativePlayback` stores per-display native intent: true after successful Apply, false after Stop or provider removal, and absent for desktop playback and legacy libraries. Launch reapplies active connected native assignments through the existing guarded Apply path and excludes them from overlay restoration and playlist advancement. A newly connected display with active native intent follows that same path; geometry-only notifications do not reapply. If a native transaction is busy, restoration retries after 0.5 seconds and rechecks connected displays and current intent before applying. Stopped displays skip automatic restoration and advancement across launches. Unsupported or mismatched-catalog builds restore desktop overlays while retaining native intent. A native restoration error is reported without starting competing overlays. Explicit desktop playback clears that display’s native intent. Provider removal disables all remembered native assignments, including disconnected displays. Pause and playlists stay independent. `make build` embeds the provider under `Contents/Extensions/` in `Flua.app`. The extension has a sandbox entitlement to read only `catalog.json`; media access still uses host wrappers. `FLUA_CATALOG_PATH` and `FLUA_WALLPAPER_IDENTIFIER` select a disposable catalog and provider identifier for integration checks. `FLUALibraryOnly` hides prototype fixtures and gives the library its own catalog group. A provider acquired from the host’s cached choice starts its catalog watcher even when no new settings request arrives. The watcher follows atomic inode replacement. Image/video session creation falls back to the existing static gradient when media cannot be read or decoded, retaining the saved descriptor and original host wrappers. A provider-owned five-second timer retries fallback media and failed AVFoundation playback while unsuspended, swapping the renderer in the same remote context only after successful construction and preserving the current presentation and saved modes. Invalidation releases the retained wrappers. Unusable or absent wrappers still require reapply for a fresh host grant. Failed catalog-access requests become retryable, and the catalog watcher republishes after a missing file returns. Cached descriptors use their host wrappers independently of the current catalog; unsupported descriptor versions still return an error.

`Library.edit` coalesces playback-setting edits for 0.5 seconds and serializes native refresh with explicit Apply. Refresh requires the embedded provider’s catalog path to match the library. `NativeWallpaperStore.refreshing` matches existing choices by provider, kind and media URLs, replaces only rendering parameters and preserves each descriptor’s surface modes and unknown configuration fields. The guarded store transaction rereads choices under the Flua lock, backs up before writing and verifies the retained descriptors after reload. A no-op refresh does not pause or restart WallpaperAgent. It does not register the provider or create new assignments.

Provider removal uses the same `NativeWallpaperBaseline.plist` as native Stop. The confirmed Settings action cancels pending native refresh, restores all remaining Flua surfaces including inherited display/Space assignments, verifies the result apart from timestamps, then unregisters the exact extension and app paths. Later foreign choices and metadata are preserved. Mixed-provider surfaces, unsafe baselines or references in `Index_v2.plist` block removal. After unregistration settles, a second guarded pass removes any cached Flua selections the host rewrites. The baseline remains available for Stop and retry; library media is retained.

The provider remains a separate compile boundary and uses private OS protocols. Native setup is exposed only on macOS 27 when the extension is embedded. Standalone test success does not establish acceptance by WallpaperAgent. Supported capabilities and remaining work are tracked in [feature status](FEATURES.md) and the [implementation plan](PLAN.md).
