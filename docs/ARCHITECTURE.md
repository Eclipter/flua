# Architecture

Flua is a local SwiftUI/AppKit application for Apple Silicon Macs running macOS 27 or later. The main app has no third-party runtime dependencies. macOS owns wallpaper playback through the embedded provider; the app has no desktop overlay playback engine.

## Application and library

- `App.swift` owns application lifecycle, windows, Settings, menu bar and library views. Shared controls honor the selected accent and Reduce Transparency. Menu bar and Dock visibility are persisted; hiding the Dock requires the menu bar icon to remain enabled.
- `Library.swift` coordinates browsing, imports, edits, persistence, playlists and native playback. A two-second timer advances playlists only when needed. Pause/Resume playlists controls automatic playlist advancement without changing wallpaper animation.
- `Model.swift` contains backward-compatible Codable state, filtering, media classifications and playlist transitions. Display assignments use stable UUIDs and retain disconnected displays. Each stores Desktop and optional Lock Screen choices with separate modes and playlist state. Linking synchronizes both surfaces; Mirrored mode synchronizes the whole pair across connected displays.
- `LibraryPaths.swift` resolves the library root. `MediaFacts.swift` inspects local media and classifies bounded thumbnails off the main thread.

`LibraryDisk` in `Model.swift` atomically writes `library.json` and `catalog.json`. Imported media is copied under `Media/`; retained still frames use `Stills/`. Direct media imports resolve symbolic links and copy the regular target file, keeping the library independent of the source. Removing an entry retains its copied media. An unreadable library manifest leaves the original file untouched and blocks saves and imports for that session.

The versioned provider catalog publishes eligible images, videos and the four built-in scenes. Rows contain stable IDs, media references, speed, dimming, fit, video trim, still time and surface modes. The catalog and each choice descriptor carry playback preferences; missing policy fields in older catalogs remain compatible. Scene still time is 7; conflicting display modes publish Animated for that surface. Blocked or unsafe entries are omitted.

## Previews, editing and imports

`Engine.swift` provides `MediaSurface` for app previews and display identification. Video and scene previews pause when hidden, offscreen or fully occluded. Video previews are explicitly silent.

`SceneView.swift` hosts an `MTKView`. `ScenePreviewRenderer.swift` shares Metal resources, and `ScenePreview.metal` renders four scenes at up to 60 fps, capped at 1280 pixels on the long edge with at most two frames in flight. A busy GPU skips frames; failed setup shows a still preview. `SceneDrawing.swift` supplies the Core Graphics reference used for thumbnails, still frames and provider rendering at up to 24 fps.

`Editor.swift` owns draft video trim/cover edits and portable package export. Export composes video tracks only, omitting source audio. Save Changes merges only video edits into the current library record, preserving details and playback settings changed while the editor was open; Cancel or closing discards drafts. `ScenePackage.swift` validates package manifests, paths and ZIP contents before copying media. Source files are preserved. Global imports reveal the added batch and retain IDs for Undo; playlist imports receive an explicit destination.

## Native wallpaper boundary

`NativeWallpaper.swift` registers and verifies the current containing app and extension, checks the catalog path, serializes transactions and invokes `FluaWallpaperGuard`. The helper validates the current-user WallpaperAgent executable and pauses it while the store is read and replaced. Commit restarts the agent; EOF, timeout or handled termination resumes an abandoned transaction.

`NativeWallpaperStore.swift` validates the private store format and resolves saved choices into Desktop and Lock Screen descriptors across targeted displays and existing Spaces. Per Display also reads live Space UUIDs from WindowServer and seeds missing store entries with their inherited choices before applying overrides; a sparse global store must not leave the ordinary Desktop on its previous wallpaper. When both choices are Flua assignments, it composes them into a v2 pair for the provider: each nested v1 config describes one surface and indexes into the union of their host-supplied file wrappers. It preserves unrelated metadata and choices; it does not read or package another provider's media. Per Display retains the global choice as the default fallback and writes targeted overrides; Mirrored updates defaults and targeted assignments. Missing or blocked saved items abort application.

During Per Display Apply, macOS can copy requested surface choices into `SystemDefault` and existing Space defaults. Apply verification and its unchanged-assignment check accept those exact choices on the matching surface while still requiring all targeted assignments and every other store value to match apart from host timestamps. Stop, removal and Mirrored verification retain their strict comparisons.

`NativeWallpaperBackup.plist` and `NativeWallpaperBackup-v2.plist` back up the last transaction for each wallpaper store. `NativeWallpaperBaseline.plist` retains previous system choices across repeated applies and edits. Normal Apply overlays only the selected assigned surfaces and preserves unassigned surfaces and untargeted displays, including their inherited choices. Stop restores targeted Flua surfaces while retaining library selections. Missing, unreadable or unusable baseline surfaces fall back to the native macOS `default` choice during Stop and provider removal; valid saved surfaces and later foreign choices are preserved. Provider removal restores remaining Flua surfaces in both wallpaper stores, unregisters the exact app/extension paths and repeats restoration to clear cached host choices. Library media is preserved.

`LibraryState.nativePlayback` records active or stopped intent per display. `nativeCleanupDisplays` durably marks displays whose removed assignments still need native cleanup, so a later reconnect or assignment refresh can finish cleanup if Flua exits before its deferred refresh. Opening Flua leaves the current system wallpaper unchanged; it does not reapply saved choices. Saved playlists wait until playback is applied again before automatically advancing, including explicit Apply, playlist start, manual advancement, reconnection or assignment refresh. Reconnection compares saved assignments with the system store and provider registration; matching choices continue without a reload. Changed assignments use guarded Apply. Stopped displays skip restoration and automatic advancement. Unavailable or mismatched builds retain intent without applying wallpapers. Explicit Apply reloads even unchanged choices to permit recovery after termination.

The inspector keeps display mode, surface linking, rendering modes and fit/speed/dimming edits in memory as a preview draft. Set Wallpapers commits that draft and assigns the selected wallpaper to the chosen surface on the target displays: the selected display in Per Display mode, or every connected display in Mirrored mode. Linked Desktop and Lock Screen choices remain synchronized, and each target surface keeps its rendering mode. Configuration drafts store only pending display mode, surface linking and rendering mode changes and merge them into the current assignments for preview and application. Removing a wallpaper or advancing a playlist while a draft is open therefore does not restore stale assignments. Drafts do not enter the persisted library or provider catalog before application. Editor playback edits and removal of active assignments are coalesced for 0.5 seconds. Parameter refresh matches provider, kind and media URLs, preserves surface modes and unknown configuration fields, and skips no-op reloads. Removal refreshes first restore Flua-owned surfaces from the baseline, preventing deleted choices from leaving stale selections. Ordinary Apply, reconnection restoration and playlist changes overlay saved choices without clearing unassigned surfaces.

## Provider

`Sources/WallpaperExtension/` is a separate compile boundary using private macOS protocols. `make build` embeds a sandboxed provider under `Contents/Extensions/`. Its file-read exception covers only `catalog.json`; media access uses host-supplied scoped wrappers. `FLUA_CATALOG_PATH` and `FLUA_WALLPAPER_IDENTIFIER` select disposable integration builds. A launch without `--data-dir` opens the directory containing that catalog. `FLUALibraryOnly` hides standalone prototype fixtures.

The provider watches catalog writes and atomic replacements, including acquisition from cached host choices. It accepts legacy v1 single-content descriptors and v2 paired Flua configs. `default` uses the paired Desktop config; locked and idle use the Lock Screen config. When those configs differ, the provider rebuilds media and replaces the layer on the existing remote context, retaining the wrapper union for recovery. Suspension preserves the selected content and its saved mode. A real-host check confirmed the v2 switch for cosmos Desktop and ember Still Lock Screen on one built-in display. File-media pairs, mixed Flua/non-Flua pairs and multiple displays remain unverified. `PlaybackPolicy.m` reads IOKit power sources, macOS Low Power Mode and each display’s current managed Space once per second while sessions exist. The provider combines preference pauses with host suspension and resumes only when both clear. Preferences continue working without the main app: catalog replacements update active sessions, and the last valid catalog policy survives transient read failures. On a cold start without a readable catalog, cached descriptors provide the fallback policy. Previews ignore preference pauses. Fullscreen applies only to Desktop presentation on the request’s `directDisplayID`; missing display affinity or unavailable private Space APIs leave fullscreen pause inactive. Power pauses also apply to locked and idle playback. Missing or undecodable media uses a static gradient; a five-second retry while unsuspended can rebuild the selected renderer in the same remote context. Missing or unusable wrappers require explicit reapply for fresh grants. Cached descriptors can render independently of the catalog; unsupported descriptor versions return an error.

Protocol details and recorded host checks live in the [provider documentation](../Sources/WallpaperExtension/README.md) and [protocol reference](../Sources/WallpaperExtension/PROTOCOL.md).

## Verification boundary

`SmokeRunner.swift` requires isolated paths and disables system Apply, Stop, restoration, refresh and removal while retaining persistence and descriptor validation. It checks app previews and workflows; native host behavior is tested separately. See [DEVELOPMENT.md](DEVELOPMENT.md) for procedures, [FEATURES.md](FEATURES.md) for support and [PLAN.md](PLAN.md) for unresolved work.
